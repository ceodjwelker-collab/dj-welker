The idea

A working DJ's setup is a mess of tabs and apps: one thing for visuals, another for mixing, a soundboard somewhere else, a request system, and a spreadsheet for what the night actually made. LIFTWAVE is the decision to stop shipping those as separate products and build one app where they're modules of a single system — so a show runs from one place and the data (songs, presets, events, earnings) is shared across all of it.

The modules

01

The visual performance engine — live visuals that react to the set.

02

03

04

Paid song requests, priority bids, tipping, queue, and earnings — the live module already shipping.

05

LIBRARY & EVENTS

Songs, logos, visual presets, and sound packs, plus saved shows, QR links, and event history.

06

EARNINGS

AUXTION revenue, fees, payouts, refunds, and reports in one ledger.

◉ Proof: architected as one app with shared data across modules, not separate codebases. AUXTION is live today; the surrounding platform is in build.

One app, four kinds of user

The hard part of LIFTWAVE isn't any single feature — it's designing one system that serves very different people without splintering. The same production app has to let DJ run his own shows end to end, let paying creators operate their own branded workspaces, let venues run recurring event workspaces, and let a guest open an event-specific request page without ever touching the operator dashboard — all under one owner/admin layer that manages users, plans, content, fees, and support.
